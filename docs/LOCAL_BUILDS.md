# Local Android builds

All Android artifacts are built on this machine. There are no cloud builds.

## Why WSL

`eas build --local` runs the real EAS build pipeline locally, and that pipeline
needs a Linux/macOS host. The build therefore runs inside WSL against a clone of
this repo on the WSL ext4 filesystem (`/root/mechbazar`), not over `/mnt/c`:
Gradle on a DrvFs mount is slow enough to look hung, and file permissions do not
survive the crossing.

The Android SDK lives at `/opt/android-sdk` in the WSL image; JDK 17 and Node 22
are already on the login shell's PATH.

## Building

From the repo root on Windows:

```powershell
.\build-local.ps1                                   # APK, the 3 OTP apps
.\build-local.ps1 -Apps mobile -Profile production  # AAB for Play upload
```

The script syncs the current branch into the WSL clone, copies each app's
signing material across, and runs the build. Artifacts land in the app's
directory inside WSL; the script prints the command to copy one back out.

**Commit first.** EAS archives committed state, so uncommitted work is silently
absent from the artifact. The script warns and prompts if the tree is dirty.

## Signing

Release builds must **not** use the debug keystore. The Expo template wires
`release { signingConfig signingConfigs.debug }` by default, which signs with the
universal Android debug key — identical on every machine, registered nowhere in
Firebase, and rejected outright by Play.

`android/` is gitignored and regenerated by prebuild, so editing `build.gradle`
does not stick. Instead each app carries a `credentials.json` (gitignored — it
holds the keystore and key passwords in plaintext) and its `eas.json`
preview/production profiles set `credentialsSource: "local"`.

The keystores are the ones EAS already holds, so their SHA-256 fingerprints are
the ones registered in Firebase. Do not generate new ones casually: changing the
signing key breaks in-place updates for anyone who already installed the app.

### Regenerating credentials.json

If a `credentials.json` or `release.keystore` is missing, pull it back from EAS
(the account still stores the credentials even though builds run locally):

```bash
# per app, e.g. @mechbazar/mobile
npx eas-cli credentials --platform android
```

Then verify the fingerprint matches what Firebase has registered for that
package, or phone auth cannot attest the app:

```bash
keytool -list -v -keystore apps/<app>/release.keystore -alias <alias>
```

Expected SHA-256 values (Firebase project `mech-bazar-8fd86`):

| App | Package | SHA-256 prefix |
|---|---|---|
| mobile | `com.mechbazar.mobile` | `0850b86d…` |
| mechanic | `com.mechbazar.mechanic` | `d7e0a46b…` |
| rider | `com.mechbazar.rider` | `3af5a6b7…` |
| seller-mobile | `com.mechbazar.seller` | `d95be999…` |
| admin-mobile | `com.mechbazar.admin` | `879ddb1a…` |

Confirm a built artifact is signed correctly with:

```bash
keytool -printcert -jarfile <artifact>
```
